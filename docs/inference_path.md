## 1. 推理路径到底是什么

一个模型有**两条**计算路径，它们跑的是同一组权重，但几乎每个工程性质都不同。

| | 训练路径 | 推理路径 |
|---|---|---|
| 时间维度 | **并行**：整个序列一次算完 | **串行**：一个 token 一个 token |
| 状态 | 无状态，每个 batch 独立 | **有状态**：KV cache 跨步骤存活 |
| dropout / 随机性 | 开 | 关（`model.eval()`） |
| 梯度 | 需要，激活值全部留着 | 不需要（`torch.no_grad()`） |
| batch 的构成 | 同构：所有样本等长 | 异构：各请求长度不同、到达时刻不同 |
| 瓶颈 | **算力**（compute-bound） | prefill 算力、decode **显存带宽**（memory-bound） |
| 数值精度要求 | 宽松，噪声甚至有益 | 严格，误差会沿生成过程累积 |
| 位置信息 | 天然从 0 开始，下标即位置 | 必须显式告知（`start_pos`） |

**「推理路径」就是这一整列的第二栏。** 它不是「把 forward 跑一遍」，而是一套独立的机制：状态生命周期、位置簿记、mask 语义、两阶段调度（prefill / decode）、采样。

nanoGPT 原版**没有**这条路径。`CausalSelfAttention.forward(self, x)` 是纯函数，`generate()` 每步重跑整个前缀。这是 Karpathy 的有意取舍：它是训练仓库，为可读性放弃了推理效率。

对普通 GPT 而言，这只是**性能问题**。
对 MLA 而言，这是**功能缺失**——MLA 存在的唯一理由就是压缩 KV cache，没有 cache，这个架构就没有在做它该做的事。

### decode 为什么是带宽瓶颈

这是理解推理的关键一点，也是 MLA 的立足点。

decode 时每步只处理 1 个 token，但**必须把全部模型权重从显存读一遍**，还要把整个 KV cache 读一遍。算术强度（每读一个字节做多少次运算）极低，GPU 的算力单元大部分时间在等数据。

所以：**decode 阶段，省显存读取量 ≈ 省时间。** MLA 把每 token 每层要读的数字从 `2·n_head·head_dim` 降到 `kv_lora_rank + qk_rope_head_dim`，省的既是容量也是带宽。而**矩阵吸收**更进一步——连解压那一步的读写都省掉。

## 2. 什么是恒等变换

**恒等变换（identity transformation）= 改变计算过程，但不改变计算结果的重写。**

数学上：如果 `f` 是模型，`f'` 是优化后的实现，那么对任意输入 `x`

```
f'(x) = f(x)       （允许浮点舍入误差，不允许语义差异）
```

日常里到处都是恒等变换：

- `a*b + a*c` → `a*(b+c)`：结果相同，乘法少一次。
- 记忆化递归：`fib(n)` 存下中间结果。**结果一模一样**，复杂度从指数降到线性。
- 数据库加索引：查询结果不变，扫描量变了。

**KV cache 就是记忆化。** `k_j` 和 `v_j` 是「已经确定的 token」的函数，算一次和算一百次结果完全相同，所以存下来复用。

### 三类改动，必须分清

改模型的时候，你做的每一件事都属于且只属于其中一类：

| 类别 | 定义 | 例子 | 验收方式 |
|---|---|---|---|
| **① 改变模型** | `f' ≠ f`，模型学到的东西变了 | 换 MHA 为 MLA、加 MoE、改 RoPE 布局、改 `v_head_dim` | 只能**重训 + 比 val loss** |
| **② 恒等变换** | `f' = f`，只是算得更快/更省 | KV cache、矩阵吸收、FlashAttention、算子融合、`torch.compile` | **等价性断言**，立刻可验 |
| **③ 近似** | `f' ≈ f`，有意接受可控误差 | int8/int4 量化、滑动窗口注意力、剪枝 | 断言 + **误差上界**，再比下游指标 |

**这个分类是你改模型时最有用的一把尺子。** 因为它直接决定了：

- 类别 ① 你**必须重训**，任何不重训的结论都是假的；
- 类别 ② 你**绝不该重训**，重训只会掩盖 bug——你应该断言它和旧实现逐位相同；
- 类别 ③ 介于两者之间，你需要先断言「误差在预期范围内」，再看下游。

**把 ② 当成 ① 来验证，是最常见的浪费**：花两小时重训，看 loss 差不多，就说「cache 应该没问题」。而实际上 cache 的 bug 根本不影响训练 loss（训练不走 cache），你验证的是一个和 bug 无关的量。

## 3. 为什么 KV cache 是纯粹的优化

三个理由，层层递进：

**① 被缓存的量是「过去」的确定性函数。**
`k_j = W_K x_j`（或 MLA 里 `c_kv_j = norm(W_DKV x_j)`）只依赖 token `j` 及其之前的内容。生成第 `t` 个 token 时，`j < t` 的这些量已经**永久固定**，不可能再变。存下来和重算一遍，在数学上是同一个数。

**② 它不改变任何一个可学习参数。**
cache 里没有权重，只有中间激活值。模型的参数、架构、前向公式，一个字都没动。

**③ 注意力对「历史」的读取方式没有变。**
位置 `i` 依然只看到 `≤ i` 的位置，读的还是那些 K/V，权重还是同一个 softmax。变的只是这些数**从哪来**：从「刚算出来的」变成「上次算好存着的」。

所以 `f'(x) = f(x)` 是一个**定理**，不是一个愿望。

### 那为什么实际上经常写错？

因为 cache 引入了**状态**，而状态和输入可能不同步。这才是全部难度所在：

| 出错点 | 具体形态 | 是否报错 |
|---|---|---|
| **位置** | 解码时 RoPE 用了 `freqs[:1]` 而不是 `freqs[start_pos:start_pos+1]` | ❌ 静默 |
| **mask** | `is_causal=True` 按左上角对齐，decode 时把整段历史屏蔽掉 | ❌ 静默 |
| **索引** | cache 写入/读出位置差 1 | ❌ 静默 |
| **生命周期** | 上次生成的残留没清，被当成历史 | ❌ 静默 |
| **模式** | 忘了 `model.eval()`，带 dropout 噪声的 latent 被存进 cache 污染整段后续 | ❌ 静默 |

**五个坑，五个都是静默的。** 它们不抛异常，只是让生成质量变差——而「生成得不好」在小模型上太容易被归因成「模型太小/训得不够」。

这就是为什么**必须**有等价性测试：它把五个静默错误全部收敛成一个布尔值。

### 反例：这些不是恒等变换

分清楚才有意义：

- **滑动窗口注意力**（只看最近 N 个 token）——丢弃了信息，是**近似**。
- **量化 KV cache**（fp16 → int8）——有精度损失，是**近似**。
- **PagedAttention / continuous batching**——是恒等变换（只改内存布局和调度），所以它们也应该有等价性测试。
- **投机解码**——整体是恒等的（草稿必须被主模型逐 token 验证接受），但草稿模型本身不是。这是个精妙的设计：**用一个不精确的东西，通过验证机制，得到一个精确的结果。**

## 4. 由此得到的方法论

一条可以直接用的规则：

> **凡是声称「只是优化」的改动，都必须能写出一条等价性断言。写不出来，说明它其实改变了模型，你只是还没意识到。**

`test_mla.py` 就是这条规则的落地。它验证五组等价：

```
1. 有 cache 的生成      == 无 cache 的生成          (贪心，逐 token 相等)
2. 吸收路径             == 朴素路径                 (W_UK 折进 Q，W_UV 折到输出后)
3. 分两块 prefill       == 一次 prefill             (验证偏移 mask)
4. 连续两次 generate    == 第二次单独跑             (验证 cache 重置)
5. 改动未来 token       不影响过去位置的 logits      (因果性没有被 cache 破坏)
```

两个必须的实现细节：

- **必须用贪心（`temperature=0.0`）**。采样有随机性，两条路会因 RNG 状态不同而分叉，测试就没意义了。
- **必须 `model.eval()`**。否则 dropout 让两条路必然不同，你会得到一个永远失败的测试。

在这个仓库里，7 种配置 × 5 组断言全部通过，包括 `v_head_dim` 解耦、q-LoRA、MHA 回退、无 RoPE 等分支。

## 5. 成熟系统的推理路径长什么样

分五层。**层次划分本身比每层的细节更值得记住**——它告诉你哪些东西该进模型文件，哪些不该。

| 层 | 职责 | 代表实现 |
|---|---|---|
| **① 模型定义** | `forward(x, start_pos, use_cache)`；prefill/decode 两个 regime；吸收路径 | 本仓库 `model_mla.py` |
| **② 缓存管理** | 分配、复用、驱逐、前缀共享；分页（把 cache 切成固定块，像虚拟内存） | vLLM 的 PagedAttention |
| **③ 请求调度** | continuous batching：不等整批做完，谁结束谁走、谁来了谁插进来 | vLLM / TGI / SGLang |
| **④ 采样与约束** | temperature / top-p / repetition penalty / JSON 结构化约束 / logit bias | 各框架的 sampler |
| **⑤ 服务** | 流式返回、超时、限流、多卡分片、指标 | 上述框架的 server |

### prefill 和 decode 是两个不同的计算问题

这是整个推理工程最重要的一条认知：

| | prefill | decode |
|---|---|---|
| 一次处理 | 整个 prompt（几百到几万 token） | 1 个 token |
| 瓶颈 | **算力** | **显存带宽** |
| 优化手段 | FlashAttention、分块、算子融合 | KV cache、**吸收**、量化、投机解码、MQA/GQA/**MLA** |

**MLA 是一个纯粹为 decode 阶段设计的架构。** 它在 prefill 阶段甚至略微更慢（多了一次低秩解压）。理解这一点，你才明白为什么它值得——因为对话式应用里，decode 的 token 数远多于 prefill，且 decode 是串行的、无法用并行掩盖。

### 一个训练仓库该做到哪一层

**做到 ①，最多摸一下 ②，剩下的不碰。**

理由：③④⑤ 是服务问题，和「模型架构对不对」完全正交，塞进训练仓库只会污染可读性——而可读性正是 nanoGPT 这类仓库的全部价值。

本仓库的取舍就是这样：实现了完整的 ①（含吸收），②只做了最简单的预分配 + 长度断言（超过 `block_size` 直接拒绝，而不是实现滑动窗口）。**主动划定边界，比做全更重要。**

## 6. 训练侧要为推理付什么代价

「训练模型要怎么为推理买单」——答案是：**架构选择在训练时决定，账单在推理时才寄到。** 而且很多账是不可退的：模型训完了，架构就锁死了。

| 训练时的选择 | 推理时的账单 |
|---|---|
| **MHA** | KV cache 最大。`2·n_head·head_dim` / token / layer |
| **MQA / GQA** | cache 小很多，但质量有损；**必须训练时就定**，事后只能靠 uptraining 补救 |
| **MLA** | cache 最小且质量损失小，但要求正确的 nope/rope 拆分，否则拿不到吸收 |
| **学习式 `wpe`** | 上下文长度**硬锁死**在 `block_size`，无法外推 |
| **RoPE** | 可以靠 NTK / YaRN 等手段外推；**decoupled 与否决定了能否吸收** |
| **`v_head_dim` 绑死 qk** | 白付 `W_UV` 和 `W_O` 的参数与算力 |
| **tie embedding** | 省一份 `vocab × n_embd` 权重（decode 时要读的权重更少） |
| **大词表** | 每步 decode 的 `lm_head` 矩阵乘更贵，且它无法被 cache |
| **Pre-LN vs Post-LN** | 影响能否安全做层融合与低精度推理 |
| **激活函数 / 归一化的选择** | 决定有没有现成的高性能融合算子可用 |

**结论：任何「只考虑训练指标」的架构决策，都在盲选一张未来的账单。**

这正好回答了「为什么 MLA 必须把推理写出来」——不写，你就永远不知道自己选的这个架构到底买到了什么。本仓库的实测是：**cache 小 6.00×，decode 快 3.89×（朴素 cache）到 6.16×（含吸收）**。这些数字必须被测出来，而不是从论文里抄。

## 7. 从 0 做一个模型，第一天就该考虑的清单

按「越早定越好」排序。越靠前的，事后改代价越大。

### 第一天就要定（改了要重训）

- [ ] **位置编码方案**：RoPE / ALiBi / 学习式。决定了上下文能不能外推。
- [ ] **注意力形态**：MHA / MQA / GQA / MLA。**直接决定推理成本的量级。**
- [ ] **如果用 RoPE + 低秩**：nope/rope 怎么拆？拆不对就拿不到吸收。
- [ ] **归一化**：Pre-LN（几乎总是）、RMSNorm vs LayerNorm、latent 上要不要 norm。
- [ ] **词表与 tokenizer**：影响 `lm_head` 成本和一切下游。
- [ ] **是否 tie embedding**。
- [ ] **`block_size`**：cache 预分配、位置表长度都以它为准。

### 第一天就该**写**（不是留到以后）

- [ ] **两条路径的骨架**：`forward(x, start_pos, use_cache)` 从一开始就带这两个参数，哪怕暂时不用。**事后加，要改遍整条调用链**（本仓库就是这么补的，`Block` / `GPT` / `generate` 全部要动）。
- [ ] **等价性测试的框架**：哪怕只有一条 `cached == uncached`。它是你后续每一次改动的安全网。
- [ ] **fallback 开关**：`kv_lora_rank=0` 退回 MHA、`use_rope=False` 退回 `wpe`。**没有开关就没有对照实验。**
- [ ] **参数量与 cache 量的打印**：`get_num_params()` 和 `kv_cache_numbers_per_token()`。没打印就等于没观测。
- [ ] **实验记录文件**：第一次跑之前就建好，而不是跑完二十次以后回忆。

### 可以延后但要留接口

- [ ] 分页 / 滑动窗口 cache（先用 `assert` 明确拒绝超长，别装作支持）
- [ ] 量化
- [ ] 投机解码 / MTP
- [ ] 张量并行、专家并行

### 一条总的判断标准

> 每加一个东西，先回答：**它属于类别 ①（改变模型）、②（恒等变换）还是 ③（近似）？**
>
> - ① → 准备重训和对照实验，并想清楚对齐哪根轴。
> - ② → 立刻写等价性断言，绝不靠「跑一下看看像不像样」验证。
> - ③ → 先断言误差上界，再看下游指标。
>
> 答不上来，就说明还没想清楚自己在做什么。
